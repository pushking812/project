# Ask MCP server (v1)

MCP-сервер Ask. С версии 2 по умолчанию (`MCP_BACKEND=api`) его инструменты работают через HTTP API нашего сервера
`ask-code-server` (`http://127.0.0.1:8737`, задачи, файлы, память, сессии, браузер, наблюдения, диагностика, 69 инструментов: 60 через API и 9 локальных Office/VBA).
Список инструментов, соответствие эндпоинтам и устройство модулей — в [MCP_TOOLS.md](MCP_TOOLS.md). Прежние инструменты
ниже остались рабочими и включаются `MCP_BACKEND=legacy` (или `both`: тогда они называются `legacy_ask`, `legacy_get_usage`,
`legacy_code`).

## Прежние инструменты (MCP_BACKEND=legacy), прямые вызовы https://ask.oryxml.com

- `ask(prompt, model?, system?)` — вопрос модели, возвращает полный текст ответа.
- `get_usage()` — текущие лимиты (`GET /v1/usage`), не расходует лимит.
- `code(task, model?, max_steps?)` — Ask правит файлы проекта по вашему указанию через `/v1/code` (читает, ищет, пишет, правит; команды не запускает), возвращает JSON с итогом. Запись и чтение ограничены корнем проекта (`ASK_CODE_ROOT`, по умолчанию папка `server.py`); `.env`, `.git`, `.venv` закрыты. Расходует лимит тарифа.

## Установка (Windows)

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
```

В `.env` одна строка без кавычек: `ASK_API_KEY=sk-ask-...`. Не публикуйте этот файл; если проект попадёт в git, добавьте `.env` в `.gitignore`.

## Быстрый старт (ps1-скрипты)

Нужны два окна PowerShell. Если запуск скриптов запрещён политикой выполнения, один раз выполните в окне `Set-ExecutionPolicy -Scope Process Bypass` или запускайте так: `powershell -ExecutionPolicy Bypass -File .\run_server.ps1`.

Окно 1, сервер (оставьте открытым, остановка: Ctrl+C):
```
.\run_server.ps1
.\run_server.ps1 8100
```
Необязательный аргумент задаёт порт (по умолчанию `8000`, хост `127.0.0.1`). Без `ASK_API_KEY` и без `.env` скрипт выведет предупреждение, но сервер всё равно запустится.

Окно 2, проверка:
```
.\run_check.ps1
.\run_check.ps1 --ask
.\run_client.ps1
.\run_client.ps1 get_usage
.\run_client.ps1 "Что такое MCP?"
.\run_client.ps1 ask "Что такое MCP?"
```
- `run_check.ps1` печатает `[OK]`/`[FAIL]` по шагам; код выхода 0 при успехе, 1 при ошибке. С `--ask` добавляется короткий вызов `ask` (тратит немного лимита).
- `run_client.ps1` без аргументов показывает инструменты и вызывает `get_usage`. Первый аргумент `get_usage` делает то же самое явно (лимит не тратится). Любой другой текст уходит в `ask` как вопрос (тратит лимит); слово `ask` в начале отбрасывается, поэтому `ask Что такое MCP?` и `Что такое MCP?` равнозначны. Вопрос, который должен начинаться со слова `ask` или `get_usage`, этим способом не отправить.
- `ASK_URL` по умолчанию собирается из `ASK_HOST` и `ASK_PORT`. Для другого порта достаточно `$env:ASK_PORT = '8100'` перед запуском.

Скрипты переходят в свою папку, поэтому их можно запускать из любого места. Ключ в них не записан.

Если клиент пишет `ConnectError: All connection attempts failed`, сервер не запущен. Если подключение проходит, а `get_usage` возвращает ошибку про `ASK_API_KEY`, у сервера нет ключа: задайте его в `.env` или `set ASK_API_KEY=...` перед запуском сервера и перезапустите его. Ключ нужен только серверу, а не клиенту.

## Настройки MCP в Cline

Cline хранит подключённые MCP-серверы и их переменные окружения (`env`) в файле:

`C:\Users\user\.cline\data\settings\cline_mcp_settings.json`

(в самом Cline: MCP Servers → Installed → Configure MCP Servers). Если в `env` блока нашего сервера задан `ASK_OFFICE_ROOT`, он сильнее рабочей папки сервера для `read_excel`, `write_excel`, `read_word`, `edit_word`. После правки файла перезапустите MCP-сервер в Cline. Ключи из этого файла не копируйте в заметки и чат.

## Параметры запуска server.py

Аргумент командной строки у `server.py` один: `--http`. Остальное задаётся переменными окружения.

| Запуск | Режим |
|---|---|
| `.venv\Scripts\python server.py` | stdio (по умолчанию): сервер запускает MCP-клиент (Claude Desktop, Claude Code, Inspector) как дочерний процесс. Порт не открывается. |
| `.venv\Scripts\python server.py --http` | постоянный HTTP-сервер (Streamable HTTP) на `http://127.0.0.1:8000/mcp`. К нему подключаются `client.py`, `check_mcp.py` и Inspector в режиме Streamable HTTP. Остановка: Ctrl+C. |

Переменные окружения:

| Переменная | Где нужна | Значение по умолчанию |
|---|---|---|
| `ASK_API_KEY` | серверу, обязательна | нет. Если не задана, ключ читается из файла `.env` рядом с `server.py` (образец: `.env.example`) |
| `ASK_BASE_URL` | серверу | `https://ask.oryxml.com` |
| `ASK_HOST` | серверу, только с `--http` | `127.0.0.1` |
| `ASK_PORT` | серверу, только с `--http` | `8000` |
| `ASK_URL` | `client.py` и `check_mcp.py` (адрес сервера) | `http://127.0.0.1:8000/mcp` |
| `MCP_BACKEND` | серверу | `api` (`legacy`, `both`) |
| `ASK_LOCAL_URL` | серверу (адрес нашего API) | `http://127.0.0.1:8737` |
| `ASK_ALLOW_REMOTE` | серверу и боту: разрешить адреса не с этого компьютера | пусто (`1`, `true`, `yes`) |
| `MCP_NAME`, `MCP_GROUPS`, `MCP_SKIP_GROUPS` | серверу: имя и набор групп инструментов (обычно задаёт `run_server.ps1`) | `ask`, все группы |
| `ASK_SESSION_AUTO`, `ASK_SESSION_ID`, `ASK_SESSION_FILE` | автосессия MCP: выключатель (`0`, `false`, `no`, `off`), заданный id, файл с id | включена; `%APPDATA%\ask-code\mcp-session.json` |
| `ASK_CODE_ROOT`, `ASK_OFFICE_ROOT`, `ASK_OFFICE_ALLOW_ANY_PATH` | корни legacy-инструментов и Office; `ASK_OFFICE_ALLOW_ANY_PATH=1` снимает ограничение корнем | корень проекта |
| `ASK_LANG` | язык подсказок анализа | `ru` (`en`) |

Полный список всех переменных `mcp\.env` с умолчаниями и пояснениями — в [`.env.example`](.env.example). Node-сервер (`npm start`) `.env` не читает: его переменные (`ASK_KEY`, `ASK_ROOT`, `ASK_PORT` и др.) задаются в окне перед запуском, см. `docs/api-stage1.md` и `docs/api-stage3.md`. Пустые значения в `.env` игнорируются.

Пример с другим портом (cmd):
```
set ASK_PORT=8100
.venv\Scripts\python server.py --http
set ASK_URL=http://127.0.0.1:8100/mcp
.venv\Scripts\python check_mcp.py
```
(`ASK_URL` задаётся во втором окне, где запускается клиент.)

Параметры `model` и `system` относятся не к запуску, а к вызову инструмента `ask`.

## MCP Inspector

Inspector — веб-интерфейс для ручного вызова инструментов MCP-сервера. Нужен Node.js. Устанавливать пакет отдельно не требуется: `npx` скачает его сам (флаг `-y` отвечает «да» на вопрос об установке).

### Минимальная проверка

Самый короткий способ убедиться, что MCP-сервер работает (ключ для этого не нужен):

1. Запустите Inspector: `npx -y @modelcontextprotocol/inspector .venv\Scripts\python.exe server.py`.
2. Нажмите **Connect**: статус должен стать Connected. Значит, сервер стартует и говорит по протоколу MCP.
3. **Tools** → **List Tools**: в списке есть `ask` и `get_usage`. Значит, инструменты зарегистрированы.
4. По желанию `get_usage` → **Run Tool**. С ключом придёт JSON с лимитами (лимит не тратится), без ключа — понятная ошибка про `ASK_API_KEY`. Ошибка без ключа тоже означает, что сервер отвечает.

Без браузера то же самое делает `check_mcp.py` (нужен запущенный `server.py --http`):
```
.venv\Scripts\python check_mcp.py
```
Он печатает `[OK]` или `[FAIL]` по каждому шагу, код выхода 0 при успехе и 1 при ошибке.

### Режим stdio (рекомендуется)

Сервер запускайте без `--http`: Inspector сам стартует его, как это делает Claude Desktop.

1. Откройте cmd в папке проекта и задайте ключ в том же окне, где будет `npx`:
   ```
   cd C:\Users\user\ask-project
   set ASK_API_KEY=sk-ask-ВАШ_КЛЮЧ
   ```
2. Запустите Inspector:
   ```
   npx -y @modelcontextprotocol/inspector .venv\Scripts\python.exe server.py
   ```
3. Дождитесь адреса вида `http://localhost:6274/?MCP_PROXY_AUTH_TOKEN=...`. Если браузер не открылся сам, откройте адрес целиком, вместе с токеном.
4. В левой панели проверьте: Transport Type — **STDIO**, Command — `.venv\Scripts\python.exe`, Arguments — `server.py`. Нажмите **Connect**, статус должен стать Connected.
5. Вкладка **Tools** → **List Tools**: должны появиться `ask` и `get_usage`.
6. Выберите `get_usage` → **Run Tool**. Придёт JSON с лимитами, лимит вызов не тратит.
7. По желанию выберите `ask` и в `prompt` введите `ответь одним словом: pong`. Этот вызов расходует немного лимита.

### Режим Streamable HTTP

Если подключение через Command и Arguments не работает:

1. В одном окне запустите сервер:
   ```
   set ASK_API_KEY=sk-ask-ВАШ_КЛЮЧ
   .venv\Scripts\python server.py --http
   ```
2. В Inspector выберите Transport Type **Streamable HTTP**, URL `http://127.0.0.1:8000/mcp`, нажмите **Connect**.

Сервер в этом режиме слушает только `127.0.0.1` и не имеет аутентификации, не открывайте его в сеть.

### Примеры вызова инструментов

#### `ask`

Через поля формы:

1. Подключитесь (**Connect**), откройте **Tools** → **List Tools** и выберите `ask`.
2. Справа заполните поля:
   - `prompt` — `Переведи на английский: добрый день` (обязательное);
   - `model` — `claude-haiku-5-5` (необязательное, пустое поле оставьте как есть);
   - `system` — `Отвечай одним предложением.` (необязательное);
   - `history` — предыдущие сообщения диалога `[{"role": "user", "text": "…"}]`, до 400: уточняющий вопрос без пересказа контекста (необязательное). Если сервер сжал историю, в результате будет поле `folded` (`{summary, count}`).
3. Нажмите **Run Tool**. В блоке результата появится текст ответа. Вызов расходует лимит.

То же в виде JSON. В новых версиях Inspector у инструмента есть переключатель на JSON-ввод; если его нет, значения по полям соответствуют этим аргументам:
```json
{
  "prompt": "Переведи на английский: добрый день",
  "model": "claude-haiku-5-5",
  "system": "Отвечай одним предложением."
}
```
Минимальный запрос, только с обязательным полем:
```json
{ "prompt": "ответь одним словом: pong" }
```

Так выглядит запрос протокола MCP, который Inspector отправляет серверу (его видно во вкладке History):
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "ask",
    "arguments": { "prompt": "ответь одним словом: pong" }
  }
}
```
#### `get_usage`

Инструмент без параметров, лимит не расходует, поэтому подходит для первой проверки с ключом.

Через поля формы:

1. Подключитесь (**Connect**), откройте **Tools** → **List Tools** и выберите `get_usage`.
2. Полей для заполнения нет: оставьте форму пустой.
3. Нажмите **Run Tool**. В блоке результата появится JSON с лимитами (без ключа — ошибка про `ASK_API_KEY`).

Аргументы в виде JSON (пустой объект):
```json
{}
```

Запрос протокола MCP (вкладка History):
```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "get_usage",
    "arguments": {}
  }
}
```

Структура ответа зависит от API (`GET /v1/usage`); точный вид полей зависит от вашего тарифа.

### Как понять результат

- Connected и два инструмента в списке — MCP-сервер работает.
- Ошибка про `ASK_API_KEY` — у процесса сервера нет ключа: задайте его в `.env`, в окне, где запущен `npx` (или сервер `--http`), либо в Inspector в панели **Environment Variables**, затем нажмите Disconnect и Connect.
- Ошибка `unauthenticated` — ключ неверный.
- Если порт 8000 уже занят старым процессом, `netstat -ano | findstr :8000` покажет его PID, закрыть можно через `taskkill /PID <pid> /F`.

## Прокси: Base URL для Cline/Continue

`openai_proxy.py` — OpenAI-совместимый вход поверх Ask (`/v1/chat/completions`, `/v1/models`, `/v1/usage`, `/healthz`). Тот же ключ Ask и тот же лимит; запрос, ретраи и дочитывание обрыва делает ядро `server.py`.

1. В `.env` задайте `PROXY_TOKEN` — пароль прокси для агента. Он обязателен и не должен совпадать с `ASK_API_KEY`: токен попадает в конфиг Cline/Continue, ключ Ask там быть не должен. Иначе прокси не стартует (код выхода 2).
2. Запуск: `.\run_proxy.ps1` — порт `127.0.0.1:8789`; второй экземпляр — `.\run_proxy.ps1 -Port 8790` (адрес — `-ProxyHost`). Остановка: Ctrl+C. Порт и хост задаёт скрипт: `-Port` важнее переменной `PROXY_PORT`, оставшейся в окне от прошлого запуска, и умолчание важнее её тоже. Напрямую (`.venv\Scripts\python openai_proxy.py`) порт берётся только из `PROXY_PORT`, иначе `8789`. Два экземпляра делят `.env` и `PROXY_TOKEN`, а счётчики `get_usage` у каждого процесса свои.
3. В клиенте: Base URL `http://127.0.0.1:8789/v1`, API key — значение `PROXY_TOKEN`, модель — любая из `GET /v1/models` (`ask` и незнакомые имена обслуживает `PROXY_MODEL`).

| Переменная | Значение по умолчанию |
|---|---|
| `PROXY_TOKEN` | нет, обязательна |
| `PROXY_HOST` | `127.0.0.1` (внешний адрес запрещён) |
| `PROXY_PORT` | `8789` (`-Port` у `run_proxy.ps1`; параметр и умолчание важнее переменной) |
| `PROXY_MODEL` | `claude-sonnet-5-5` |
| `PROXY_TOOL_RESULT` | `20000` — знаков в одном результате инструмента (раньше было `8000` и обрезало `read_files` по нескольким файлам). Длиннее обрезается с пометкой `[…обрезано]`, в логе `truncated: true`. Большие результаты занимают место в окне `LIMIT_PROMPT` и вытесняют историю. |
| `PROXY_ACCESS_LOG` | по умолчанию включён: на каждый входящий запрос (в том числе отклонённый с 401 и 404) одна строка JSON в stderr и в `PROXY_LOG_FILE` с `"access": true`: метод, путь, статус, `auth_header` (был ли заголовок), `token_ok` (подошёл ли токен), `client`, `user_agent`, `ms`. Токен и тело не пишутся. `off` отключает. |
| `PROXY_LOG_FILE` | файл, куда дописываются те же строки, что идут в stderr (запросы и access-строки). Если не задан, `main()` ставит `project\proxy.log`; пустое значение отключает запись в файл, но только если это настоящая переменная окружения (`$env:PROXY_LOG_FILE = ''`): пустую строку в `.env` читалка пропускает. Файл не ротируется. |
| `PROXY_COMPACT_AT` | `0.7` — доля `LIMIT_PROMPT`, после которой прокси сжимает начало истории в резюме (0.1–0.95); `off` отключает. См. «Автосжатие» ниже |
| `PROXY_BACKEND` | `ask` — прежний путь через `/v1/ask`; `code` — режим через наш сервер и `/v1/code` (см. «Режим `code`» ниже) |
| `PROXY_CODE_MODE` | только для `PROXY_BACKEND=code`: `all`, `edits` или `plan`; если не задана, берётся `ASK_MODE` сервера |
| `PROXY_TOOLS_BLOCK` | `60000` — знаков в каталоге инструментов, который прокси кладёт в промпт. Инструменты добавляются по одному, не влезшие пропускаются (в логе `tools_dropped`, `tools_dropped_names`). При прежних `25000` Cline видел 35 из 69 инструментов `ask__*` |
| `PROXY_NOTES_FILE`, `PROXY_NOTES_CHARS` | заметки проекта для режима `ask`: файл (по умолчанию `ASK.md` в корне проекта, `off` отключает) и лимит знаков (`4000`). Читаются при каждом запросе |
| `PROXY_TOOL_FIRST` | `ask__` — префиксы имён, которые идут в каталог первыми (через запятую) |
| `PROXY_TOOL_EXCLUDE` | `craft,=composio_,=team_` по умолчанию — подстроки имён серверов, исключаемых из каталога (через запятую). Запись с `=` убирает родные инструменты клиента, у которых в имени нет `__`, по префиксу: `craft,=composio_` уберёт `composio_search_tools` |
| `PROXY_SLIM_SCHEMA` | `on` — прокси убирает из схем параметров `title`, `default: null` и вариант `null` в `anyOf` (имена параметров и `required` остаются, исходная схема не меняется); `off` отключает |
| `PROXY_TOOLS_DUMP` | `mcp/tools-seen.txt` — файл, куда прокси пишет имя и размер каждого инструмента, который прислал клиент (исключённые помечены `[исключён]`); `off` отключает |
| `PROXY_TOOL_POLICY` | `ask` — `ask`, `native`, `mcp` или `off`: чем пользоваться для действий, родными инструментами клиента или MCP |

В строке лога есть `catalog_chars` (размер каталога инструментов) и `history_chars` (размер истории), а `GET /v1/models` отдаёт `context_length` и `max_context` — грубую оценку окна: `LIMIT_PROMPT` ÷ 3. Читает ли это поле ваш клиент, зависит от клиента. Размер каталога по группам и самые тяжёлые инструменты показывает `python measure_tools.py` (из `mcp/`).

**Несколько MCP-серверов.** `server.py` читает `MCP_NAME` (имя сервера, по умолчанию `ask`), `MCP_GROUPS` (только эти группы, например `office,vba`) и `MCP_SKIP_GROUPS` (все, кроме этих); неизвестная группа даёт ошибку. Офис и браузер отдельным сервером: основной с `MCP_SKIP_GROUPS=office,vba,browser` на порту 8000, второй с `MCP_NAME=ask-extra`, `MCP_GROUPS=office,vba,browser`, `ASK_PORT=8001` (`http://127.0.0.1:8001/mcp`). Оба запускает `run_servers.ps1` (или `run_server.ps1 -Part main|office`). Имена инструментов второго станут `ask-extra__…`, прокси ставит их сразу после `ask__…`. По умолчанию всё работает как одним сервером.

Разговор уходит в Ask по документации: `history` с ролями `user`/`assistant` (вызовы инструментов — как JSON `{"tool": …, "args": …}`, результаты — сообщения «Результат инструмента …»), в `prompt` — только новейшее сообщение с каталогом инструментов, протокол и правила — в `system`. Вызов, написанный посреди текста, тоже распознаётся.

Как у оригинального клиента `ask-code`, история хранит шаги, а не содержимое: в старых шагах (кроме двух последних) результат инструмента урезан до 400 знаков с пометкой «всего N знаков; прочитайте заново», а длинные строки в `args` вызова (код, текст файла) — до 300. Если сервер сжал историю (событие `folded`), прокси запоминает резюме (до 32 штук, в памяти) и в следующем запросе с тем же началом подставляет пару `[Earlier in this conversation, folded into notes]` + резюме вместо свёрнутых реплик; в логе поля `folded` (сколько реплик свёрнуто) и `folded_applied` (сколько заменено). Повтор при 503 `restarting` и 429 с `Retry-After` делает общий слой `ask_stream`.

Автосжатие (как `/compact` у `ask-code`): когда запрос (prompt + history) переходит `PROXY_COMPACT_AT` (доля `LIMIT_PROMPT`, `0.7` по умолчанию, допустимо 0.1–0.95, `off` — выключено), прокси один раз делает тихий запрос `/v1/ask` с просьбой написать резюме (цель, файлы, команды, решения, что сделано и что открыто; без инструментов) по устоявшейся начальной части истории. Две-три последние реплики остаются как есть. Резюме хранится так же, как `folded`, и подставляется парой `[Earlier in this conversation, folded into notes]` + резюме. Каждое сжатие тратит один вопрос лимита; после неудачи следующая попытка не раньше чем через 5 минут, история тогда режется, как прежде. В логе поле `compacted` — сколько реплик заменено резюме.

**Режим `code` (опыт).** `PROXY_BACKEND=code` в `mcp\.env` (по умолчанию `ask`, прежний путь через `/v1/ask`). В этом режиме прокси не просит модель писать JSON-вызовы: он берёт последнее сообщение пользователя (без `<environment_details>` и обёртки `<task>` Cline) и отдаёт его нашему серверу (`POST /execute`, адрес `ASK_LOCAL_URL`), который ведёт настоящий цикл `/v1/code`. Модель сама читает и правит файлы в `ASK_ROOT` и запускает команды, а Cline получает поток текста: её слова и строки `▸ имя_инструмента путь`. Путь прокси берёт из поля `path` события `tool` нашего сервера; он есть только у вызовов с путём (файловые инструменты), а команды и шаблоны поиска сервер в событие не кладёт, поэтому у `run_command` и `search` в строке только имя. Отказ или сбой вызова помечен `(отказ/сбой)`. В конце задачи прокси добавляет блок «Сделано на компьютере»: до 20 записей из `done.steps` сервера (по 120 знаков), то есть то, что сервер выполнил на самом деле, а не пересказ модели. Инструменты Cline в этом режиме не используются, поэтому его подтверждения и диффы не работают; режим `mode` задаёт `PROXY_CODE_MODE` (`all`, `edits`, `plan`; иначе берётся `ASK_MODE` сервера). Историю помнит сессия сервера: её id `cline-<хеш первого сообщения>-<ГГГГММДДЧЧММСС>` (время UTC, когда прокси впервые увидел задачу), то есть одна задача Cline — одна сессия. Если то же первое сообщение пришло без продолжения диалога спустя час (`_SESSION_GAP`), это новая задача с новым временем; таблица времён живёт в памяти, после перезапуска прокси текущая задача получит новое время. Нужен запущенный `npm start`, `ASK_ROOT` должен указывать на проект, с которым работает Cline. В логе прокси `backend: "code"`, `session`, а также `used_delta` (расход этого запроса, например `{"week": 0.5, "window": 0.05}`) и `session_used` (сумма недельных единиц по сессии и число запросов, `{"week": 1.0, "requests": 2}`). Расход считается как разница двух ответов `GET /me` нашего сервера до и после запроса (таймаут 3 секунды); если `/me` не ответил или окно лимита сбросилось между замерами, полей нет. Одновременный запрос из другого окна попадёт в тот же расход, а сумма по сессии хранится в памяти и обнуляется при перезапуске прокси. Смотреть: `Select-String -Path project\proxy.log -Pattern session_used`. Смена режима — перезапуск прокси.

**Выбор режима: `ask` или `code`.**

| | `ask` (по умолчанию) | `code` |
|---|---|---|
| Куда идёт запрос | прокси → `POST /v1/ask` сайта | прокси → `POST /execute` нашего сервера (8737) → `/v1/code` сайта |
| Инструменты у модели | нет; прокси вставляет в `system` описание инструментов Cline и разбирает JSON-вызов из текста | серверные: `list_files`, `read_file`, `search`, `write_file`, `edit_file`, `run_command`, `browser` |
| Кто их выполняет | Cline (родные, MCP `ask` / `ask-extra`, подтверждения и диффы работают) | наш сервер на вашей машине, Cline только показывает поток |
| `.clinerules` | доходят (в системном сообщении Cline) | не доходят, только `ASK.md` |
| Контекст | прокси ужимает сам (каталог 60 000, результат 20 000, закрепление, сжатие, автосжатие) | историю ведёт сессия сервера |
| `npm start` | не нужен | нужен |
| Стоимость шага | один вопрос лимита `/v1/ask` | доля счётчика `/v1/code` (по перехвату около 0,04 недельного на запрос) |
| Отказы модели | бывают («файлы править не могу»), прокси повторяет запрос | в перехвате не наблюдались |

Минусы `code`: около 12 тыс. входных токенов на каждое обращение к модели (в основном `ASK.md` и правила сайта); служебные сообщения Cline («вы не использовали инструмент») могут быть приняты за новое задание и потратить лимит (в `proxy.log` такие запросы помечены `no_task_tag` и `prompt_head`); результаты вызовов в чате не видны, показаны только путь файла (`▸ write_file путь`) и итоговый список «Сделано на компьютере»; родные инструменты Cline и MCP не участвуют.

Если `PROXY_BACKEND=code` стоит в `mcp\.env`, обычный `start_servers.ps1` тоже поднимет прокси в режиме `code`; `tap_start.ps1` задаёт режим в окне прокси и `.env` не меняет. Для обычной работы поставьте `PROXY_BACKEND=ask` или удалите строку.

Цифры по стоимости и отказам получены на нескольких коротких заданиях, на длинных задачах режимы не сравнивались.

**Перехват обмена оригинального клиента** (`code_tap.py`): локальный «отвод» между `ask-code.mjs` и сайтом. Запуск: `python code_tap.py` (порт `TAP_PORT`, по умолчанию 8790, пересылает на `TAP_SITE`, по умолчанию `https://ask.oryxml.com`). Клиент запускают так: `$env:ASK_SITE='http://127.0.0.1:8790'; $env:ASK_KEY='...'; $env:ASK_NO_UPDATE='1'; node vendor\ask-code.mjs`. Каждый запрос, ответ и SSE-событие пишутся строками JSON в `project\tap\<дата-время>.jsonl`. Ключи и заголовок `Authorization` скрыты; строки длиннее 2000 знаков режутся (`TAP_FULL=1` оставляет целиком). Файлы содержат содержимое вашей папки, `tap/` в `.gitignore`.

Второй перехват — весь путь Cline → прокси (`PROXY_BACKEND=code`) → наш `/execute` → отвод → сайт — поднимает одной командой `test\tap_start.ps1` (из любой папки: `powershell -ExecutionPolicy Bypass -File project\test\tap_start.ps1`). Скрипт останавливает серверы (`stop_servers.ps1`), освобождает порт 8790 и открывает три окна: отвод, `npm start` с `ASK_SITE=http://127.0.0.1:8790` и `ASK_ROOT`, прокси с `PROXY_BACKEND=code`. `-Root` задаёт папку, в которой работает модель (по умолчанию `C:\Users\user\Desktop\workai`), `-Stop` только останавливает. Ключ берётся из `$env:ASK_KEY` или запрашивается скрыто; MCP-серверы (8000, 8001) не запускаются. Вернуть обычный режим: `stop_servers.ps1`, затем `start_servers.ps1`.

В режиме `code` модель получает от Cline только последнее сообщение и `ASK.md` из `ASK_ROOT` (поле `notes`); `.clinerules` и системное сообщение Cline до неё не доходят, поэтому нужные правила держите в `ASK.md` (до 20 000 знаков, длиннее обрезается).

Прокси отвечает не больше чем на два запроса одновременно. Слишком большой вход обрезается (system 20 000 символов, история 400 сообщений, промпт 100 000, результат инструмента `PROXY_TOOL_RESULT`, по умолчанию 20 000) с пометкой в ответе и `truncated: true` в логе. Первое сообщение пользователя (задача, до 4 000 знаков) всегда остаётся в начале истории. На каждый ход в `stderr` и в `PROXY_LOG_FILE` пишется одна строка JSON (длины, статус, usage, limits; без ключей и текста промпта). Каждый запрос расходует лимит тарифа, `/v1/models` и `/healthz` — нет.

## Telegram-бот

`telegram_bot.py` — управление MCP-сервером из Telegram: задачи, статус, файлы, сессии, браузер, диагностика.
Бот подключается к уже запущенному `server.py --http` (`TELEGRAM_MCP_URL`, по умолчанию `http://127.0.0.1:8000/mcp`),
наружу ничего не открывает (long polling), пускает только id из `TELEGRAM_ALLOWED_USER_IDS` и по умолчанию
работает в режиме `plan`.

`start_servers.ps1` бота по умолчанию не запускает (строка `Telegram Bot [--] отключён`). Включить: `$env:START_BOT = '1'` перед запуском. Отдельно бот запускается через `run_bot.ps1`, как раньше.

```
cd mcp
.\.venv\Scripts\python.exe -m pip install pytest  # для тестов, если ещё нет
notepad .env                                    # TELEGRAM_BOT_TOKEN, TELEGRAM_ALLOWED_USER_IDS
.\run_server.ps1                                # MCP-сервер (или /svc start из бота)
.\run_bot.ps1
.\.venv\Scripts\python.exe check_bot.py         # токен и связь с MCP, без сообщений
```

Команды: `/help`, `/status`, `/exec`, `/plan`, `/run`, `/task`, `/stop`, `/ask`, `/tools`, `/call`, `/ws`, `/cd`, `/ls`,
`/cat`, `/sessions`, `/browser`, `/doctor`, `/svc`. Если `api.telegram.org` блокируется, задайте `TELEGRAM_PROXY` (`http://`, `https://`, `socks5://`; для SOCKS нужен
`socksio` из `requirements.txt`). Прокси используется только для Telegram: MCP-сервер остаётся локальным.

Полное описание, переменные и ограничения —
[docs/telegram-bot.md](../docs/telegram-bot.md).

## Проверка

  ```
  set ASK_API_KEY=sk-ask-...
  .venv\Scripts\python smoke_test.py
  ```
