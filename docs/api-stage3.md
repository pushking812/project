# API этапа 3

Раздел растёт по коммитам. Сейчас: workspace (3А, коммиты 1–2).

## GET /workspace

```json
{ "ok": true, "root": "C:\\Users\\me\\projects\\a", "allowedRoots": ["C:\\Users\\me"], "sessionId": null }
```

`sessionId` — текущая сессия папки `root` или `null`, если сессий ещё нет.

## POST /workspace

Тело: `{"path": "<папка>", "mode": "all|edits|plan"}` (`mode` необязателен). Относительный путь считается от текущего корня.

Успех: `200 {ok:true, root, changed:true, sessionId}`. Если папка и так текущая: `200 {ok:true, root, changed:false, already_current:true, sessionId}`, ничего не останавливается.

Проверки идут в таком порядке, первая сработавшая отвечает:

| Статус | `code` | Причина |
|---|---|---|
| 400 | `invalid_path` | не строка, пустая, управляющие символы |
| 403 | `plan_mode` | режим `plan` (смена корня — изменение) |
| 403 | `system_path` | корень диска, `C:\Windows`, `C:\Program Files*`, `C:\ProgramData`; на Unix `/etc`, `/usr`, `/var`, `/bin`, `/sbin`, `/boot`, `/lib*`, `/dev`, `/proc`, `/sys` — сами папки и всё внутри, кроме `/var` и `C:\ProgramData`: закрыты только они сами, подпапки (`/var/www/site`) проходят дальше на проверку `ASK_ALLOWED_ROOTS` |
| 403 | `home_forbidden` | сама домашняя папка (подпапки можно) |
| 403 | `not_allowed` | вне `ASK_ALLOWED_ROOTS` |
| 404 | `not_found` | нет такой папки или это файл |
| 409 | `tasks_running` | идёт задача `/execute` или `/start` |

Пути сравниваются после `realpath` (ссылки раскрываются). На Windows регистр не важен.

После смены: `config.root` новый; окно `/browser` закрыто (следующий шаг откроет новое); наблюдатели `/watches` остановлены и сброшены; приложения `/command` остановлены. Сессии и память считаются от нового корня сами. Каждая смена пишется в лог: `[INFO] [workspace] root changed: X → Y (by request)`.

Кто держит корень, регистрируется в `app.onWorkspaceChange` (как `app.onShutdown`): хук получает `{from, to}` после смены.

## Последний корень запоминается

После успешного `POST /workspace` сервер пишет новый корень в `%APPDATA%\ask-code\last-root.json` (Linux и macOS: `~/.config/ask-code/last-root.json`; путь меняет `ASK_ROOT_FILE`). При старте, если `ASK_ROOT` не задан, он берёт корень из файла, но только если папка существует и проходит те же проверки, что и `POST /workspace` (системные папки, домашняя папка, `ASK_ALLOWED_ROOTS`). Иначе корень остаётся по умолчанию (текущая папка). `ASK_ROOT` сильнее файла. `ASK_REMEMBER_ROOT=0` выключает запоминание. Код: `lib/last-root.mjs`, тесты: `test/last-root.mjs`.

## ASK_ALLOWED_ROOTS

Папки через `;` (Windows) или `:` (Unix), только абсолютные. Не задана: подпапки домашней папки и `ASK_ROOT`, если он вне неё. Если задана и содержит корень диска, домашнюю папку целиком или системную папку, сервер не запускается (`exit 1`).

## `files` в `/ask`, `/execute` и `/start` (3Б)

В `files` передают **пути** внутри корня: строки или `{"path": "..."}`. Сервер читает файлы сам, как `read_file`, и кладёт их в `files` запроса к сайту (формат из `docs/Ask API docs.txt`, «Files and pictures»).

```json
{ "prompt": "опиши файл", "files": ["notes.txt", "shots/screen.png"], "useContext": false }
```

| Файл | Что уходит на сайт |
|---|---|
| текст, код | `{kind:"text", name, text}`, до 200 000 символов, остаток обрезается (`… (truncated)`) |
| Office (`.xlsx`, `.docx`, …) | `{kind:"text", name, text}` (текст документа) |
| картинка | `{kind:"image", name, mediaType, data}` (base64) |
| PDF | `{kind:"text"}` с текстом и страницы как `{kind:"image"}` (пока их общее число не превысит `ASK_FILES_MAX`) |

Лимиты: `ASK_FILES_MAX` (по умолчанию и максимум 5), `ASK_FILES_MAX_BYTES` (по умолчанию и максимум 30 000 000 — сумма текста и base64).

Ошибки приходят до начала потока и до создания задачи:

| Статус | `code` | Причина |
|---|---|---|
| 400 | `invalid_files` | `files` не список, пустой путь или не строка |
| 400 | `refused` | путь указывает на папку |
| 403 | `secret` | `.env`, ключи и другие секретные файлы |
| 403 | `outside` | путь вне корня (`../..`, чужой диск). Полный путь внутри корня сервер сам делает относительным |
| 404 | `not_found` | файла нет |
| 413 | `too_many_files` | больше `ASK_FILES_MAX` |
| 413 | `too_large` | сумма больше `ASK_FILES_MAX_BYTES` |

В `/execute` и `/start` файлы уходят в первом запросе задачи; сессию (`session_id`) они не меняют. Файлы в историю сессии не сохраняются.

Формат один (как в документации сайта). Переключателя `ASK_FILES_FORMAT` из ТЗ нет: документация формат подтверждает, а для `GET /v1/docs` у сервера нет разбора.

## `output_files` в `/execute` и `outputFiles` в `/status` (3Б)

Файлы, которые задача создала или изменила. Пути относительные от корня, с `/`, без повторов, в порядке появления. До 100 имён.

- `/execute`: событие `done` получает `output_files: ["report.md"]`.
- `/start` → `GET /status/:id`: поле `outputFiles`. Оно заполняется по ходу задачи, а не только в конце.
- Если файлов нет, поле **опускается** (как `session_id`): прежний набор ключей не меняется.

Откуда берутся имена:

| Источник | Что считается |
|---|---|
| `write_file`, `edit_file` | вызов прошёл (`ok`). Отказы, режим `plan`, пути вне корня и записи в память Ask (`remembered …`) не считаются. |
| `run_command` | папка сравнивается до и после команды: файлы, которые появились или изменились (размер, время правки). Так видны `.xlsx` и `.docx`, которые модель делает скриптом: инструментов `write_excel` и `write_word` в ask-code нет. |

Ограничения сравнения для `run_command`:

- Не заходит в папки с точки, `node_modules`, `__pycache__`, `dist`, `build`, `target`, `venv`, `.venv`.
- Смотрит не больше 5000 файлов. Если в папке больше, вердикта по команде нет (иначе имена были бы случайными).
- Попадает всё, что команда записала в проект: лог тестов, кеш, `package-lock.json`. Модель не отличает «результат» от побочного файла. Отключить: `ASK_OUTPUT_SCAN=0`, тогда остаются только `write_file` и `edit_file`.
- Файл, который задача создала и сама удалила, в список не попадает.
- Файл, который изменил фоновый процесс (`cmd &`) уже после команды, не виден.

## Тесты `files` и `output_files` (коммит 59)

Подставной сайт, настоящий сервер, настоящие файлы. Ключ не нужен.

| Файл | Что делает |
|---|---|
| `test/fixtures.mjs` | создаёт `.xlsx` (лист «Sales»), одностраничный `.pdf` (латиница) и `calc.py` без внешних библиотек |
| `test/stack.mjs` | поднимает сервер и подставной сайт во временной папке с этими файлами; можно запустить отдельно: `node test/stack.mjs` |
| `test/integration-files.mjs` (входит в `npm test`) | `.xlsx`, `.py`, `.pdf` по отдельности и вместе в `/ask`; цикл `/execute` → `report.xlsx` → `output_files` → `/ask`; то же через `/start` и `outputFiles`; отказы для `.env` и `../` |
| `mcp/tests/test_files_integration.py` | запускает `stack.mjs` и вызывает инструменты MCP: `analyze` (read и write), `review`, `summarize`, `explain`, `ask` и `execute` с `files` |

- Скрипт, создающий `report.xlsx`, подставной сайт присылает сам. Проверяется путь `run_command` → `output_files`, а не то, что настоящая модель напишет такой скрипт.
- Тесты PDF идут, если в PATH есть `pdftotext` (poppler); без него пропускаются. PDF с кириллицей и скан-PDF не проверены.
- При тестах сервер печатает «Ask wants to run… $ node -e …». Это его обычный вывод, не ошибка.
- Запуск: `npm test` (Node) и `cd mcp && python -m pytest` (MCP).
