## 2. Что сделано

- **2А Файлы и команды:** `/read`, `/list`, `/search`, `/write`, `/edit`, `/command`. Секреты и пути за пределами папки отклоняются.
- **2Б Память и заметки:** `/notes`, `/remember`, `/memory` (GET, POST, DELETE), `/memory/:topic`.
- **2В Сессии:** `/sessions` (GET, POST), `/sessions/resume`, `/sessions/:id`, `/sessions/:id/export`, поле `session_id` в `/execute` и `/start`.
- **2Г Браузер:** `POST /browser` со всеми действиями (open, read, screenshot, click, type, press, scroll, console, back, viewport, close, handoff), приватные поля, обнаружение капчи, `allowedSites`, ограничения по режимам.

- **2Е Context, compact, model, диагностика:** `/context`, `/status`, `/compact`, `/models`, `/model`, `/doctor`, `/bug`.
- **Режим окна по запросу:** поле `headless` в `/browser`, `/execute`, `/start`; `ASK_BROWSER_HEADLESS` задаёт только значение по умолчанию.
- **Капча:** поле `captcha` (`manual` или `handoff`), переменная `ASK_CAPTCHA`. В режиме `handoff` сервер сам показывает окно и зовёт человека. Капчу проходит человек.
- **Документация:** `docs/api-stage2.md` (все эндпоинты, подробное описание действий браузера), `docs/api-stage1.md`, `MODEL.md`, `postman/` (коллекция и `curls.txt`).

- **MCP-сервер (по отдельной просьбе, это уже этап 3):** инструменты `mcp/` переделаны под наш HTTP API (52 инструмента), прежние `ask`, `get_usage`, `code` оставлены в `ask_mcp/legacy/` и включаются `MCP_BACKEND=legacy|both`. Описание: `mcp/MCP_TOOLS.md`.

## 4. Что не по ТЗ

**Отклонения (расхождение с текстом ТЗ)**
- **Окно браузера одно на сервер**, а не на сессию (ТЗ §12 предлагает mutex). Шаги идут по очереди.
- **`browser` в `/execute` и `/start`:** окно у каждой задачи своё, а не общее с `POST /browser`.
- **Нет `--no-sandbox`:** класс `AskBrowser` из ask-code его не принимает. ТЗ §12 предлагает флаг как митигацию.
- **`handoff` в `plan` запрещён** (403). В ТЗ такого запрета нет.
- **`export` в `plan` отвечает 403.** В ТЗ этого нет.
- **`DELETE /memory`** требует режим `all`; `edits` тоже даёт 403.
- **Событие `folded`** сайта не обрабатывается: сессия обрезается до лимита ходов.
- **Идентификаторы сессий постоянны** (указатель на текущую в файле), потому что `resumeSession` из ask-code переименовывает файлы.
- **Неизвестный корректный `session_id`** создаёт сессию, а не даёт ошибку.
- **Шаг браузера дольше 30 с** отвечает 504, но в браузере может ещё завершиться.
- **Число эндпоинтов:** ТЗ §13 говорит о 30, в `docs/api-stage2.md` таблица из 33 (добавлены `GET /browser`, `POST /browser/handoff/done` и другие).

**Дополнения, которых в ТЗ нет**
- `POST /browser/handoff/done`, `GET /browser`, поле `headless`, поле `captcha` и `ASK_CAPTCHA`, `browser` и `allowedSites` в `/execute` и `/start`.
- Капчу сервер не решает: её проходит человек. Это решение разработки, а не требование ТЗ.

**Расхождение в документах**
- `docs/api-stage1.md` пишет, что `edits` запрещает команды везде. В `/execute` это верно, прямой `/command` блокирует только `plan` (см. `MODEL.md`).
- Для `plan` интерактивный ask-code добавляет к запросу пометку `PLAN_NOTE`, наш `/execute` не добавляет.

1. Перезапустить `npm start`, затем `python mcp\smoke_test.py`: `browser_state` должен вернуть JSON.

4. `/bug` с пометкой «тест» на настоящем сайте.
5. Postman-коллекцию запустить в приложении.
6. Ctrl+C на Linux или macOS: сервер и окно браузера закрываются.
