# Режимы работы с моделью: `all`, `edits`, `plan`

Режим говорит серверу, что модели можно делать в вашей папке. Он не меняет саму модель. Модель выбирается отдельно: `GET /models` и `POST /model`.

Допустимые значения: `all`, `edits`, `plan`. Любое другое значение даёт `400 bad_mode`. Режима `act` нет, ближе всего к нему `all`.

## Что разрешено в каждом режиме

| | `all` | `edits` | `plan` |
|---|---|---|---|
| Чтение файлов, поиск | да | да | да |
| Запись и правка файлов (`write_file`, `edit_file`) | да | да | нет |
| Запуск команд | да, без вопросов | нет, вопрос получает «нет» | нет |
| Открытие внешних сайтов в браузере | любые | только из `allowedSites` | только из `allowedSites`, и только просмотр |
| `localhost` и файлы проекта в браузере | да | да | да, только просмотр |
| Секретные файлы (`.env` и т. п.) | не трогает | не трогает | не трогает |

Секреты и пути вне папки проекта защищены во всех режимах, `all` их не открывает.

## Как задать режим

- **По умолчанию для сервера:** переменная `ASK_MODE`. В cmd: `set ASK_MODE=plan`, затем `npm start`. Если не задана, берётся `all`.
- **Для одного запроса:** поле `mode` в теле. Оно сильнее `ASK_MODE`.

```
curl -N -X POST http://127.0.0.1:8737/execute -H "Content-Type: application/json" -d "{\"prompt\":\"add a LICENSE file\",\"mode\":\"plan\"}"
```

Поле `mode` принимают `/execute`, `/start`, `/write`, `/edit`, `/command`, `/browser`, `/watches` и другие эндпоинты этапа 2. Для сессии режим задаётся в каждом запросе, в сессии он не хранится.

## Режимы по эндпоинтам

- **`/execute` и `/start`** (модель работает сама): режим определяет, что она может делать, как в таблице выше. Вопросы модели к пользователю решает правило из `lib/mock-input.mjs`: «да» только на «Allow this change», остальное «нет». Спросить некого, поэтому всё, что в режиме требует подтверждения, отклоняется.
- **`/write`, `/edit`, `/command`** (прямые вызовы без модели): `plan` даёт `403 plan_mode`. `edits` их разрешает, потому что диалога подтверждения здесь нет.
- **`/browser`:** `all` открывает любые сайты. В `edits` и `plan` внешний сайт открывается, только если его хост есть в `allowedSites`. Клик, уводящий на чужой сайт, откатывается с `403 site_not_allowed`. В `plan` доступны `open`, `read`, `screenshot`, `scroll`, `console`, `back`, `viewport`, `close`.
- **`POST /execute` с `browser: true`:** у задачи своё окно. Правила сайтов те же. `handoff` без `"headless": false` в запросе (или `ASK_BROWSER_HEADLESS=0`) отклоняется. С `"captcha": "handoff"` (или `ASK_CAPTCHA=handoff`) окно задачи при капче на пути само становится видимым и зовёт человека; капчу проходит только он.
- **`export` сессии:** в `plan` даёт `403`.
- **`DELETE /memory`:** нужен именно `all`. В `edits` и `plan` ответ `403`.

## Как режим связан с промтом

**Режим задаётся не текстом промта.** Фраза «ничего не меняй» или «работай в режиме plan» в поле `prompt` режим не включает. Права определяют только `mode` в теле запроса и `ASK_MODE`. Если не указать ни то ни другое, действует `all`, как бы ни был написан промт.

**Что видит модель в каждом режиме (`/execute`, `/start`):**
- Текст `prompt` уходит на сайт ask без изменений. Пометку о режиме сервер к нему не добавляет.
- В `plan` модель узнаёт о запрете, когда пробует записать файл или запустить команду. Инструмент отвечает ей: «Plan mode is on: nothing is changed or run yet. Put this step in your plan». После этого она обычно пишет план словами.
- В `edits` отказ на команду она тоже получает от инструмента, а не из промта.
- Интерактивный ask-code в `plan` сам добавляет к промту пометку: «Plan mode: the person wants a plan before any change… End with a short numbered plan». Наш сервер этого не делает. Поэтому в `plan` результат лучше, если попросить план в самом промте.

**Как формулировать промт под режим:**

| Режим | Что писать в `prompt` | Пример |
|---|---|---|
| `plan` | Попросить план и не просить действий | «Посмотри, как устроена авторизация, и дай нумерованный план перехода на JWT» |
| `edits` | Называть файлы и правки, не просить запускать команды | «В `lib/config.mjs` добавь переменную `LOG_LEVEL` со значением по умолчанию `info`» |
| `all` | Можно просить и правки, и запуск | «Исправь падающий тест и запусти `npm test`» |

Просьба, которую режим не разрешает, не ломает задачу. Модель получает отказ инструмента и сообщает, что не смогла этого сделать. Например, «запусти тесты» в `edits` закончится ответом, что команды запрещены.

**Типичная связка «план, потом выполнение»:**
1. `POST /execute` с `"mode":"plan"` и промтом «составь план…». Файлы не меняются.
2. Прочитать план.
3. `POST /execute` с `"mode":"all"` или `"edits"` и промтом «выполни пункты 1–3 плана». Для памяти между шагами используйте один `session_id`, тогда модель помнит свой план.

Этот порядок я описал по коду, на настоящем сайте ask его не гонял.

## Какой режим выбрать

- **`plan`:** посмотреть код и получить план, ничего не меняя. Безопасно для первого знакомства с папкой.
- **`edits`:** модель правит файлы, но не запускает команды и не ходит на чужие сайты. Подходит для рефакторинга и правок текста.
- **`all`:** модель правит файлы, запускает команды (тесты, сборку) и открывает сайты. Используйте в папках, которым доверяете.

## Что проверено

Режимы проверены на подставном сайте (`npm test`). На настоящем сайте ask `plan` и `edits` не прогонялись. Живой тест `npm run test:live` идёт в режиме по умолчанию.
